## 三、反风控核心模块设计

### 3.1 通道账号池（核心模块）

**问题**：单个 Stripe 账号交易额超阈值会被风控
**方案**：维护多账号池，按健康度路由

#### 数据库设计
```sql
-- 通道账号池
CREATE TABLE t_channel_account (
  account_id VARCHAR(64) PRIMARY KEY,    -- 账号 ID（如 stripe_acct_001）
  if_code VARCHAR(20) NOT NULL,           -- 通道编码（stripe/paypal）
  account_name VARCHAR(128),              -- 账号显示名
  config_params JSON,                     -- 通道配置（API Key 等）

  -- 健康度指标
  daily_limit_amount BIGINT,              -- 日交易限额（分）
  monthly_limit_amount BIGINT,            -- 月交易限额
  current_daily_amount BIGINT DEFAULT 0,  -- 当日已交易
  current_monthly_amount BIGINT DEFAULT 0,-- 当月已交易

  -- 风险指标快照（由调度任务更新）
  chargeback_rate DECIMAL(8,4) DEFAULT 0, -- 拒付率
  dispute_rate DECIMAL(8,4) DEFAULT 0,    -- 投诉率
  refund_rate DECIMAL(8,4) DEFAULT 0,     -- 退款率
  success_rate DECIMAL(8,4) DEFAULT 100,  -- 成功率

  -- 状态
  health_status TINYINT DEFAULT 1,        -- 0-异常 1-健康 2-警告 3-限流
  state TINYINT DEFAULT 1,                -- 0-停用 1-启用 2-冻结

  -- 业务隔离
  risk_tier VARCHAR(10) DEFAULT 'low',    -- low/mid/high（绑定哪种风险等级商户）
  mcc_whitelist VARCHAR(1024),            -- 允许的 MCC 行业（逗号分隔）

  priority INT DEFAULT 0,                 -- 路由优先级
  created_at TIMESTAMP(3) DEFAULT CURRENT_TIMESTAMP(3),
  updated_at TIMESTAMP(3) DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),

  INDEX idx_if_code_state (if_code, state),
  INDEX idx_health (health_status)
);
```

#### 路由策略
```
入参：商户号 + 通道类型 + 订单金额
策略链：
  1. 过滤：state = 启用 & health = 健康/警告
  2. 过滤：风险等级匹配（商户风险 ≤ 账号承载等级）
  3. 过滤：MCC 在白名单内
  4. 过滤：日/月额度充足
  5. 排序：按健康度（拒付率低优先）+ 优先级
  6. 选中：Top 1 / 加权随机
```

### 3.2 通道健康度引擎

**核心数据**（每个通道账号实时计算）：

| 指标 | 计算公式 | 红线 | 黄线 |
|------|---------|------|------|
| 拒付率 | 拒付笔数 / 成功笔数（30天） | >0.9% | >0.7% |
| 投诉率 | 投诉笔数 / 成功笔数（30天） | >1% | >0.8% |
| 退款率 | 退款笔数 / 成功笔数（30天） | >8% | >5% |
| 成功率 | 成功笔数 / 总笔数（24小时） | <85% | <90% |
| 3DS 比例 | 3DS 笔数 / 总笔数 | <60% | <70% |

#### 数据库设计
```sql
-- 通道健康度时序数据（每小时一条快照）
CREATE TABLE t_channel_health_snapshot (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  account_id VARCHAR(64) NOT NULL,
  snapshot_time TIMESTAMP NOT NULL,
  window_type VARCHAR(10),                -- '1H'/'24H'/'7D'/'30D'

  total_count INT DEFAULT 0,              -- 总笔数
  success_count INT DEFAULT 0,            -- 成功笔数
  fail_count INT DEFAULT 0,               -- 失败笔数
  chargeback_count INT DEFAULT 0,         -- 拒付笔数
  dispute_count INT DEFAULT 0,            -- 投诉笔数
  refund_count INT DEFAULT 0,             -- 退款笔数

  chargeback_rate DECIMAL(8,4),
  dispute_rate DECIMAL(8,4),
  refund_rate DECIMAL(8,4),
  success_rate DECIMAL(8,4),

  total_amount BIGINT DEFAULT 0,

  INDEX idx_account_time (account_id, snapshot_time),
  INDEX idx_window (window_type, snapshot_time)
);
```

### 3.3 商户风险评分系统

**评分维度**（0-100 分，分数越高风险越大）：

```java
风险评分 = 0.3 × 拒付率得分
        + 0.2 × 投诉率得分
        + 0.15 × 退款率得分
        + 0.15 × 成功率得分（反向）
        + 0.1 × 高风险卡比例
        + 0.1 × 历史评分
```

#### 数据库设计
```sql
-- 商户风险评分历史
CREATE TABLE t_merchant_risk_score (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  mch_no VARCHAR(64) NOT NULL,
  risk_score INT,                         -- 0-100
  risk_tier VARCHAR(10),                  -- low/mid/high

  chargeback_rate DECIMAL(8,4),
  dispute_rate DECIMAL(8,4),
  refund_rate DECIMAL(8,4),
  success_rate DECIMAL(8,4),

  evaluation_window VARCHAR(10),          -- 评估窗口（如 '30D'）
  created_at TIMESTAMP(3) DEFAULT CURRENT_TIMESTAMP(3),

  INDEX idx_mch_time (mch_no, created_at)
);

-- 商户表扩展
ALTER TABLE t_mch_info
  ADD risk_tier VARCHAR(10) DEFAULT 'mid',
  ADD current_risk_score INT DEFAULT 50,
  ADD mcc_code VARCHAR(10),               -- MCC 行业代码
  ADD daily_limit_amount BIGINT,          -- 日限额
  ADD single_limit_amount BIGINT,         -- 单笔限额
  ADD chargeback_alert_threshold DECIMAL(8,4) DEFAULT 0.7,
  ADD auto_suspend_threshold DECIMAL(8,4) DEFAULT 0.9;
```

### 3.4 熔断 / 降流引擎

#### 触发规则
```yaml
rules:
  - name: 拒付率超 0.9%
    trigger: chargeback_rate > 0.009
    action: suspend_merchant         # 暂停商户
    notify: ["telegram", "email"]

  - name: 拒付率超 0.7%
    trigger: chargeback_rate > 0.007
    action: reduce_traffic           # 限流到 50%
    notify: ["telegram"]

  - name: 单账号日交易突增
    trigger: today_amount > yesterday_amount * 3
    action: pause_account            # 暂停该账号
    notify: ["telegram", "sms"]

  - name: 成功率骤降
    trigger: success_rate_1h < 70
    action: switch_account           # 切到备用账号
    notify: ["telegram"]
```

### 3.5 拒付预测（订单级）

**目标**：下单时判断是否高风险，提前拦截或强制 3DS

#### 规则引擎
```
评分项：
- 卡 BIN 风险（虚拟卡 +30, Prepaid +20）
- IP 风险（黑名单 +50, VPN +15, 高风险国 +20）
- 设备指纹（首次出现 +5, 频繁切换 +30）
- 邮箱风险（一次性邮箱 +25）
- 金额异常（远超商户均值 +20）
- 时间异常（凌晨 3-5 点 +10）
- 卡测试模式（短时多卡同 IP +40）

总分：
- 0-30：放行
- 30-60：强制 3DS
- 60-100：拒绝
```

#### 数据库设计
```sql
-- 订单风控记录
CREATE TABLE t_order_risk_record (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  pay_order_id VARCHAR(30) NOT NULL,
  mch_no VARCHAR(64),

  risk_score INT,                         -- 风险评分
  risk_action VARCHAR(20),                -- pass/3ds/reject
  risk_factors JSON,                      -- 触发的规则明细

  -- 设备指纹
  ip VARCHAR(45),
  ip_country VARCHAR(2),
  device_fingerprint VARCHAR(128),
  user_agent VARCHAR(512),

  -- 卡信息（脱敏）
  card_bin VARCHAR(8),
  card_last4 VARCHAR(4),
  card_country VARCHAR(2),
  card_type VARCHAR(20),                  -- credit/debit/prepaid

  -- 买家信息
  email VARCHAR(128),
  phone VARCHAR(32),

  created_at TIMESTAMP(3) DEFAULT CURRENT_TIMESTAMP(3),
  INDEX idx_order (pay_order_id),
  INDEX idx_mch_time (mch_no, created_at)
);

-- 黑名单
CREATE TABLE t_risk_blacklist (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  list_type VARCHAR(20),                  -- card_bin/ip/email/device/phone
  list_value VARCHAR(256),
  reason VARCHAR(256),
  expire_at TIMESTAMP,
  state TINYINT DEFAULT 1,
  created_at TIMESTAMP(3) DEFAULT CURRENT_TIMESTAMP(3),

  UNIQUE KEY uk_type_value (list_type, list_value)
);
```

### 3.6 Chargeback 证据库

**目标**：拒付发生时快速准备证据，提高申诉胜率

#### 数据库设计
```sql
-- 拒付记录
CREATE TABLE t_chargeback_record (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  pay_order_id VARCHAR(30) NOT NULL,
  channel_chargeback_id VARCHAR(128),     -- 通道方拒付 ID
  mch_no VARCHAR(64),
  account_id VARCHAR(64),                 -- 哪个通道账号

  chargeback_amount BIGINT,
  chargeback_currency VARCHAR(3),
  chargeback_reason VARCHAR(64),          -- 拒付原因码（如 4855 unrecognized）

  state VARCHAR(20),                      -- received/responded/won/lost
  evidence_due_at TIMESTAMP,              -- 证据提交截止时间
  evidence_submitted_at TIMESTAMP,

  -- 证据快照（订单创建时已收集）
  customer_ip VARCHAR(45),
  customer_email VARCHAR(128),
  shipping_address TEXT,
  receipt_url VARCHAR(512),
  customer_signature_url VARCHAR(512),

  created_at TIMESTAMP(3) DEFAULT CURRENT_TIMESTAMP(3),
  INDEX idx_state_due (state, evidence_due_at)
);
```
